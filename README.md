# av.by monitor

Приложение следит за объявлениями на [cars.av.by](https://cars.av.by) и присылает новые
подходящие объявления в Telegram. По умолчанию настроено на **частных лиц** и пометку
**«срочно»**, но фильтры можно менять через веб-интерфейс.

## Возможности

- Несколько независимых профилей поиска (например, «до 4000 $» и «внедорожники 2015+»).
- Фильтры av.by: ключевое слово, продавец, цена в USD, год, пробег, коробка передач,
  кузов, двигатель, привод, марка (163 бренда), область, цвет и произвольные
  дополнительные параметры.
- Отправка в Telegram: текст или фото с подписью и кнопкой «Открыть на av.by».
- Поддержка нескольких получателей (`chat_id` через запятую).
- Новизна определяется временем публикации: каждые 3 минуты запрашиваются
  объявления с сортировкой **«новые»**, и отправляются только те, что опубликованы
  после предыдущей успешной проверки. Первый запуск и пустая база не приводят к
  рассылке старых объявлений.
- Дедупликация: каждое объявление отправляется в Telegram только один раз, даже
  если подходит под несколько профилей.
- Повторная отправка любого объявления из истории.
- Планировщик с общим интервалом (по умолчанию 3 минуты) и переопределением
  интервала на профиль.
- Веб-интерфейс на Thymeleaf. Локально используется H2 в файле `./data/avby`,
  в production — PostgreSQL (Supabase), чтобы профили, настройки и история
  переживали перезапуски и деплои.
- Liveness-эндпоинт `/health` для внешнего пингера на бесплатном хостинге.

## Требования

- JDK 21 (проект собирается toolchain'ом на Java 21).
- Интернет для доступа к cars.av.by и api.telegram.org.

## Настройка Telegram-бота

1. Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot` и получите токен
   вида `123456789:AA...`.
2. В приложении перейдите в **Настройки**, вставьте токен и нажмите **Сохранить настройки**.
3. Напишите вашему боту в Telegram любое сообщение (например, `/start`).
4. Нажмите **Найти chat_id** — приложение покажет найденные чаты. Нажмите
   **Использовать**, чтобы подставить id.
5. Сохраните настройки и нажмите **Отправить тестовое сообщение**.

Токен хранится в базе приложения (H2 локально, PostgreSQL в production) и не
выводится обратно на страницу. Если поле токена оставить пустым при сохранении,
текущий токен сохраняется.

`chat_id` можно указать несколько через запятую или точку с запятой.

## Профили поиска

Профиль — это сохранённый фильтр av.by. Все поля, кроме названия, необязательны.

| Поле | Параметр av.by | Примечание |
|---|---|---|
| Ключевое слово | `description` | по умолчанию `срочно` |
| Продавец | `seller_type[0]` | 1 — частные, 2 — компании |
| Цена от/до, $ | `price_usd[min]` / `price_usd[max]` | добавляется `price_currency=2` |
| Год от/до | `year[min]` / `year[max]` | |
| Пробег от/до, км | `mileage_km[min]` / `mileage_km[max]` | |
| Коробка | `transmission_type[i]` | 1 автоматическая, 2 механика, 3 робот, 4 вариатор |
| Кузов | `body_type[i]` | значения из справочника av.by |
| Двигатель | `engine_type[i]` | бензин, дизель, гибрид, электро и т.д. |
| Привод | `drive_type[i]` | 1 передний, 2 задний, 3 подключаемый полный, 4 постоянный полный |
| Марка | `brands[0][brand]` | список марок с id av.by; модель задаётся через доп. параметры |
| Область | `place_region[0]` | 1001–1006 |
| Цвет | `color[0]` | 1–13 |
| Дополнительно | произвольная строка | добавляется в URL как есть, например `has_photo360=1&condition[4]=5` |

Кнопка **Открыть на av.by** у профиля открывает тот же фильтр на сайте — удобно
проверить, что параметры заданы правильно.

### Новизна, окно опроса и дедупликация

- Каждая проверка запрашивает av.by с сортировкой **`sort=4` («новые
  объявления»)**. Это важно: сортировка по умолчанию («актуальные») подмешивает
  промо и может вытеснить свежее объявление с первой страницы.
- Новым считается объявление, у которого точный `publishedAt` (из встроенного JSON
  страницы) попадает в окно: от предыдущей успешной проверки до текущего момента.
  Поэтому база больше не является источником истины «что новое».
- Первый запуск, перезапуск и даже полностью пустая база не приводят к спаму:
  монитор смотрит только на последний интервал (по умолчанию 3 минуты).
- Поднятые старые объявления (`renewedAt`) не считаются новыми: у них старый
  `publishedAt`, поэтому они пропускаются, даже если av.by показывает их первыми.
- Если сервис был выключен дольше интервала, объявления за пропущенное время не
  досылаются. Это осознанный компромисс: лучше пропустить, чем заспамить старым.
- Дедупликация **глобальная по `advert_id`**: одно и то же объявление, подходящее
  под несколько профилей, отправляется в Telegram только один раз. Таблица
  `seen_listings` — это страховка от дублей и история, а не определение новизны.
- Перед отправкой объявление «занимается» в базе (claim) и это сохраняется до
  сетевого запроса. Поэтому падение процесса или таймаут не приводят к повторной
  отправке. Повтор разрешён только тогда, когда Telegram точно не принял сообщение
  (например, HTTP 429); после неоднозначной ошибки объявление помечается
  «без подтверждения» и автоматически больше не отправляется.
- Если в настройках указано несколько `chat_id` и часть из них получила сообщение,
  отправка считается успешной — повторно в успешные чаты ничего не уходит.
- **Сбросить историю** очищает историю профиля. На новизну это не влияет: она
  определяется временем, а не историей.
- Неудачные отправки повторяются до 3 раз при следующих опросах.
- Кнопка **«Отправить снова»** в истории — единственный способ намеренно отправить
  объявление повторно; она требует подтверждения.

## Настройки приложения

|---|---|---|

## Конфигурация Spring Boot

Основные параметры в `src/main/resources/application.properties`:

```properties
server.port=${PORT:8080}
spring.datasource.url=${SPRING_DATASOURCE_URL:jdbc:h2:file:./data/avby;DB_CLOSE_ON_EXIT=FALSE}
spring.datasource.username=${SPRING_DATASOURCE_USERNAME:sa}
spring.datasource.password=${SPRING_DATASOURCE_PASSWORD:}
avby.base-url=https://cars.av.by
avby.request-timeout-seconds=30
avby.scheduling.enabled=true
avby.scheduler-tick-ms=30000
avby.scheduler-initial-delay-ms=15000
```

Без переменных окружения приложение работает как раньше — с локальной H2.
Если задать `SPRING_DATASOURCE_URL`, `SPRING_DATASOURCE_USERNAME` и
`SPRING_DATASOURCE_PASSWORD`, Spring подключится к PostgreSQL. Драйвер
PostgreSQL входит в сборку, `ddl-auto=update` создаёт таблицы автоматически.

Для тестов используется отдельный профиль `test` с H2 в памяти и отключённым
планировщиком (`src/test/resources/application-test.properties`).

### Как устроен опрос

1. `MonitorScheduler` раз в 30 секунд проверяет, каким профилям пора опрашивать.
2. `MonitorService` запрашивает у av.by страницы результатов с `sort=4` («новые»).
3. `AvbyParser` разбирает HTML-карточки и достаёт точные `publishedAt` / `renewedAt`
   из встроенного JSON `__NEXT_DATA__`.
4. Отправляются только объявления, опубликованные внутри окна (от предыдущей
   успешной проверки), и только если их ещё нет в глобальной истории отправок.
5. `seen_listings` используется для дедупликации и истории, а ошибки профиля
   сохраняются в `last_error` и видны на панели.

## Деплой на сервер (бесплатно и постоянно)

Приложению нужен **постоянно работающий процесс**: планировщик опрашивает av.by каждые
несколько минут. Есть два бесплатных пути: **Render Free + Supabase** (быстрый старт,
ничего не администрируете) и **своя VPS** (стабильнее и без засыпания). Оба описаны
ниже.

### Render Free + Supabase

Схема: приложение крутится на Render, а профили, настройки Telegram и история лежат
в бесплатном PostgreSQL от Supabase. Поэтому временный диск Render больше не проблема.

#### Шаг 1. Создать базу в Supabase

1. Зарегистрируйтесь на [supabase.com](https://supabase.com/) и создайте проект.
   Сразу сохраните пароль базы — второй раз он не показывается.
2. Откройте **Project Settings → Database → Connection string** и выберите
   **Session pooler** (не «Direct connection»).
3. Скопируйте строку. Она выглядит так:

   ```
   postgresql://postgres.<project-ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres
   ```

   Важно: у pooler-хоста имя пользователя — `postgres.<project-ref>`, а не просто
   `postgres`. Прямой хост `db.<project-ref>.supabase.co` работает только по IPv6,
   а Render — по IPv4, поэтому нужен именно pooler.
4. Для Spring Boot преобразуйте строку в JDBC-формат: замените `postgresql://` на
   `jdbc:postgresql://` и добавьте `?sslmode=require` в конец. Спецсимволы в пароле
   должны быть URL-encoded.

   ```
   jdbc:postgresql://aws-0-<region>.pooler.supabase.com:5432/postgres?sslmode=require
   ```

Таблицы создадутся автоматически при первом старте (`ddl-auto=update`).

#### Шаг 2. Задеплоить на Render

1. Запушьте репозиторий на GitHub. В корне уже лежит `render.yaml`.
2. В [Render Dashboard](https://dashboard.render.com/) нажмите **New → Blueprint**,
   выберите репозиторий и примените план. Render соберёт `Dockerfile` и создаст
   web-сервис с health check `/health`.
3. В настройках сервиса заполните переменные окружения:

   | Переменная | Значение |
   |---|---|
   | `SPRING_DATASOURCE_URL` | `jdbc:postgresql://aws-0-<region>.pooler.supabase.com:5432/postgres?sslmode=require` |
   | `SPRING_DATASOURCE_USERNAME` | `postgres.<project-ref>` |
   | `SPRING_DATASOURCE_PASSWORD` | пароль базы из Supabase |

   В `render.yaml` они помечены `sync: false`, поэтому в Git ничего не попадёт.
   **Никогда не коммитьте пароль и connection string с паролем.**
4. Дождитесь деплоя и откройте `https://<service>.onrender.com`. Настройте Telegram
   и профили как обычно — теперь они сохраняются в Supabase.

Если создаёте сервис вручную, выберите **Language: Docker**, план **Free**,
health check path `/health`. Порт Render передаёт через `PORT`, приложение уже
слушает его (`server.port=${PORT:8080}`) на `0.0.0.0`.

#### Шаг 3. Не давать сервису засыпать

Render Free останавливает сервис после 15 минут без входящего HTTP-трафика.
Планировщик внутри процесса трафиком не считается. Заведите бесплатный пингер
([cron-job.org](https://cron-job.org/), UptimeRobot) на
`https://<service>.onrender.com/health` каждые 5–10 минут.

#### Ограничения Render Free

1. **Засыпание через 15 минут** без HTTP-трафика — лечится пингером выше.
2. **Временная файловая система** — больше не важна: данные в Supabase. Локальный
   H2 на Render не используется.
3. **750 free instance hours в месяц** на workspace. Один сервис, работающий круглые
   сутки, расходует почти всё это время.
4. Бесплатный Render Postgres не подходит для долгого хранения: он истекает через
   30 дней. Поэтому и используется Supabase.
5. Бесплатный проект Supabase засыпает после недели полного бездействия, но бот
   опрашивает базу постоянно, так что на практике этого не происходит.

### Своя VPS (стабильный вариант)

Ниже — вариант с собственной виртуальной машиной и Docker. Локальная H2-база при
этом хранится в `./data` на диске сервера. Если хотите PostgreSQL и здесь, задайте
те же три переменные `SPRING_DATASOURCE_*` в `docker-compose.yml`.

### Что выбрать

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Render Free + Supabase** (проще всего) | нечего администрировать, деплой из Git, данные в Postgres | засыпает без пингера, 750 часов/мес |
| **Oracle Cloud Always Free** (стабильнее) | ARM Ampere A1: до 4 OCPU / 24 GB RAM, бессрочно бесплатно | бывает нехватка capacity; Oracle может освобождать простаивающие Always Free инстансы |
| **Google Cloud Free Tier** | e2-micro (1 GB RAM), 30 GB диск, стабильно | всего 1 GB RAM, только регионы us-central1/us-west1/us-east1 |
| Свой Raspberry Pi / старый ПК | полностью бесплатно, ваш IP | нужен интернет 24/7 и электричество |

GitHub Actions по расписанию — плохая замена: минимальный интервал 5 минут, запуски
задерживаются, а локальная H2-база не сохраняется между запусками (с Supabase данные
бы сохранились, но расписание всё равно слишком редкое).

### Шаг 1. Создать виртуальную машину

**Oracle Cloud:**
1. Зарегистрируйтесь на [oracle.com/cloud/free](https://www.oracle.com/cloud/free/).
   Карта нужна только для проверки, списаний в Always Free нет.
2. Создайте Compute Instance: образ **Ubuntu 24.04**, shape **Ampere A1**
   (Always Free eligible), 1–4 OCPU и 6–24 GB RAM, публичный IPv4.
3. Сохраните SSH-ключ. В Security List откройте только порт **22** (SSH).
   Порт 8080 наружу открывать не нужно — доступ будет через SSH-туннель.

**Google Cloud:**
1. Создайте e2-micro в одном из бесплатных регионов, образ Ubuntu 24.04.
2. Разрешите SSH. Для 1 GB RAM добавьте swap (см. ниже) и уменьшите память JVM.

### Шаг 2. Установить Docker

```bash
sudo apt update
sudo apt install -y git
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
```

Выйдите и зайдите по SSH снова, затем проверьте:

```bash

```

### Шаг 3. Скопировать проект

Если проект есть в Git:

```bash
git clone <URL-репозитория> avby

```

Либо с Windows напрямую:

```powershell
scp -r C:\avby user@SERVER_IP:/home/user/avby
```

### Шаг 4. Запустить

```bash
cd ~/avby
docker compose up -d --build
docker compose logs -f
```

Первая сборка занимает 3–5 минут. Контейнер запускается с `restart: unless-stopped`,
поэтому переживает падения и перезагрузку сервера (если Docker включён в автозапуск:
`sudo systemctl enable docker`).

### Шаг 5. Открыть интерфейс безопасно

У приложения **нет авторизации**, поэтому порт привязан к `127.0.0.1`. Не открывайте
его в интернет как есть. С рабочего компьютера поднимите SSH-туннель:

```powershell
ssh -N -L 8080:127.0.0.1:8080 user@SERVER_IP
```

И откройте [http://localhost:8080](http://localhost:8080). Настройте Telegram как обычно.

Если нужен доступ с телефона — поставьте [Tailscale](https://tailscale.com/) (бесплатно)
или Caddy/nginx с Basic Auth и HTTPS.

### Данные и резервная копия

При локальной H2 база и история лежат в `./data/avby.mv.db` на хосте, поэтому
пересборка контейнера данные не удаляет.

```bash
tar czf avby-backup-$(date +%F).tgz data/
```

Восстановление: остановить контейнер, заменить каталог `data/`, запустить снова.

Если используется Supabase/PostgreSQL, бэкап делается средствами Supabase
(**Database → Backups**) или через `pg_dump` с Session pooler-строкой. В этом
случае каталог `./data` на сервере не нужен.

### Полезные команды

```bash
docker compose ps
docker compose logs --tail=100
docker compose restart
docker compose down
```

### Если сервер с 1 GB RAM

Уменьшите память JVM в `docker-compose.yml`:

```yaml
JAVA_TOOL_OPTIONS: "-Xms96m -Xmx320m"
```

И добавьте swap:

```bash
sudo fallocate -l 1G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### Если av.by отвечает 403/429

Скорее всего, сайт ограничивает частые запросы или IP дата-центра. Увеличьте
`requestDelayMs` в настройках (например, до 3000–5000 мс) и интервал опроса.
Если блокировка по IP сохраняется — попробуйте другой регион/провайдера или запуск
с домашнего IP.

## Ограничения и советы

- av.by — сторонний сайт. Разметка может измениться; все селекторы собраны в
  `AvbyParser`, их легко поправить.
- Не ставьте слишком маленькую паузу между запросами: сайт может ответить 403/429.
  Приложение делает до 3 попыток и сообщает об ошибке в интерфейсе.
- Приложение не обходит авторизацию и работает только с публичными страницами поиска.
- Для работы планировщика приложение должно быть запущено постоянно (или запускаться
  по расписанию ОС).
